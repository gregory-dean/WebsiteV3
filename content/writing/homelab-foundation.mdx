## Why I rebuilt it

I wanted a controlled place to practice both sides of the fight: administer systems like a defender, then attack them like an adversary, without putting anyone else's network at risk. The first version lived in VirtualBox on a single Windows desktop. That was enough to learn the guests. It was not enough to learn the network.

The [Homelab repo](https://github.com/gregory-dean/Homelab) is the public build log. This page is the map.

## What sits on the desk

The lab is an 8U, 10-inch DeskPi RackMate. From the top of the cabinet: an unmanaged TP-Link LS108GP, a 12-port keystone panel, then three Lenovo Tiny PCs in printed trays.

- **Sirius**, an M720q with an i5-8400T, runs OPNsense on the metal. A four-port Intel I350 handles WAN to the ISP modem and LAN to the switch.
- **Polaris**, an M720q with an i5-9500T and 32 GB, is the primary Proxmox node. Guests live on a single-disk ZFS pool for snapshots and checksums, not redundancy.
- **Vega**, an M715q with a Ryzen 3 PRO 2200GE and 32 GB, is the second Proxmox node. Storage is ext4 with LVM-thin.
- **Sol**, the Ryzen 7 5800X Windows desktop, is the command center. I do not run the hypervisors on it.
- **Lyra**, an Archer AX6000, is house Wi-Fi in access-point mode. Sirius stays the only DHCP server on Core.

Star names stay on the metal. Role names stay on the guests.

## Two firewalls, on purpose

The switch cannot do VLANs. Everything patched into it shares one Layer 2 network I call Core, `10.10.10.0/24`. Sirius never sees traffic between two devices on the same switch, so lab isolation cannot live on the edge box alone.

**Sirius** owns WAN, house internet, Core DHCP, Core DNS, and NAT for both Core and the lab prefixes.

**gw-01** is a second OPNsense install, a VM on Polaris. It is not hardware. It routes the lab networks and nothing else. It does not NAT. Its Core address is `10.10.10.3`. The deny from the attack network to Core is a rule on gw-01.

House phones on Lyra can reach the internet. They cannot enter the lab. Sol can, on purpose.

## Isolation without VLANs

The lab is a VXLAN overlay between Polaris (`10.10.10.11`) and Vega (`10.10.10.12`). Guests on those vnets have no physical NIC. The two nodes encapsulate the frames, which is how `kali-01` on Vega reaches `dc-01` on Polaris.

- **labsrv** `10.30.10.0/24` — servers
- **labep** `10.30.20.0/24` — endpoints
- **labatk** `10.30.30.0/24` — the attack box

Sirius holds static routes for those three prefixes via gw-01. Hybrid source NAT on Sirius translates both `10.10.10.0/24` and `10.30.0.0/16` out WAN.

![Network diagram of Core, the VXLAN overlay, and the lab prefixes](/writing/homelab-network.jpg)

DNS is two zones on purpose. `home.gregory-dean.com` is Core, owned by Unbound on Sirius. `lab.gregory-dean.com` is Active Directory on `dc-01`. Sirius forwards the lab zone so Sol can resolve lab names without joining the domain.

## The range

Polaris holds the identity and visibility stack. Vega holds the off-domain boxes.

- **dc-01** — Windows Server 2022, AD DS for `lab.gregory-dean.com`
- **winclient-01** — Windows 11 Pro, domain joined
- **siem-01** — Ubuntu Server with Wazuh installed and reachable
- **ubuntu-01** — Ubuntu Server, off domain
- **kali-01** — Kali, off domain, on the attack vnet

`labatk` may reach `labsrv` and `labep`. That is the point. Servers and endpoints do not initiate toward Kali. Nothing on the range initiates toward Core.

The cluster is two nodes, one UI, no shared storage, no HA. Corosync and VXLAN ride Core. Admin SSH and the Proxmox UI accept Sol and the peer hypervisors. A phone on Wi-Fi does not.

## What is next

Wazuh is on the box. Agents, Sysmon, and detection tuning are the next pass, then attack simulation that produces telemetry I can actually hunt. Each piece of the build already has a guide in the repo: rack, firewall, hypervisor, switching, access point, command center, and guests, plus the architecture and inventory pages.

The troubleshooting notes might be the most useful part. I kept them because that is the work.
